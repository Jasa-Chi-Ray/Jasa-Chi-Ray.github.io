ChatGPT Mirror 镜像站部署教程

在 Linux VPS 上搭建自己的 ChatGPT 镜像站：从 Docker Compose 启动三项服务，到 NGINX 配置 HTTPS，再到账号池、数据备份和日常维护。

项目仓库：https://github.com/Jasa-Chi-Ray/chatgpt-mirror

关于项目

ChatGPT Mirror 将镜像访问和后台管理放在一起。管理后台使用 Vue 3、TypeScript 和 TDesign，管理服务使用 Django 5.1，数据保存在 SQLite 中，通过 Docker Compose 部署。

后台可以集中录入 Cookie 或 Refresh Token，把上游账号组织成账号池，再为用户分配访问范围、可用模型和使用限制。共享账号时，项目会在镜像可控范围内隔离对话、归档、搜索和删除等操作。

日常维护主要通过访问日志、账号状态和代理连通性完成，也可以配置禁止访问的路径。下面先展示项目界面，再介绍 VPS 部署过程。

VPS 部署教程

DOCKER COMPOSE V2

使用原仓库 docker-compose.yml 的三服务编排。以下命令在 Linux VPS 的 Bash 终端运行；HTTPS 示例假定 NGINX 与 Docker 位于同一台服务器。

01

准备 VPS 和 Docker 环境

准备一台可访问镜像仓库及上游服务的 Linux 主机、Git、Docker Engine、Compose v2 和一个可配置 DNS 的域名。容器包含浏览器组件，资源需求应结合实际并发评估。

服务关系：chatgpt-mirror 是镜像入口，默认端口 40002；django 提供管理服务，宿主机端口为 127.0.0.1:18000；cfbypass 为辅助服务，宿主机端口为 127.0.0.1:18001，并配置 1 GB 共享内存。Compose 会等待 Django 健康检查通过后再启动镜像入口。

✓ Docker Engine✓ Compose v2✓ 域名 + TLS 证书

没有安装 Docker？先按 Docker 官方安装文档 ↗完成对应系统的安装。确认当前用户有权运行 Docker，再获取项目：

BASH · 获取项目
docker --version
docker compose version
git clone https://github.com/Jasa-Chi-Ray/chatgpt-mirror.git
cd chatgpt-mirror
cp .env.example .env
chmod 600 .env

在同机 NGINX 反代方案中，先编辑 docker-compose.yml，将 chatgpt-mirror 服务的端口映射替换为下面这一行，使入口仅绑定回环地址。不要改动其他服务的端口。

YAML · CHATGPT-MIRROR → PORTS
ports:
  - "127.0.0.1:${PORT:-40002}:${PORT:-40002}"
BASH · 启动服务
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 django chatgpt-mirror cfbypass
curl -fsS http://127.0.0.1:18000/0x/user/version-cfg

三个服务启动后，Django 状态显示 healthy，版本接口返回 JSON。

当前 Compose 使用 frontend、backend、cfbypass 三个镜像标签，不使用 .env.example 中的 ALL_IN_ONE_IMAGE。按默认 docker-compose.yml 操作即可，无需切换为单容器部署。

03

配置 NGINX、域名与 HTTPS

把域名 A 记录指向服务器公网 IP；只有配置了可用 IPv6 时才添加 AAAA 记录。在云安全组中开放 80、443，保留你的 SSH 管理入口。下面使用宿主机 NGINX，不需要开放 40002、18000 或 18001。

以下示例使用同机 NGINX 反代，包含 WebSocket 和请求、响应头缓冲配置。先签发证书，再填写实际域名及证书路径。

展开完整 NGINX 配置 ＋

安装 NGINX 并为域名取得 TLS 证书后，将以下内容放入 NGINX 的 http 上下文包含的站点文件中，例如 /etc/nginx/conf.d/mirror.conf。证书路径须对应实际已签发的文件。

证书可按 Certbot 官方指南 ↗签发。首次签发前只启用 HTTP 站点，获得证书后再启用下方 443 配置，避免不存在的证书阻止 NGINX 启动。

NGINX · HTTPS + WEBSOCKET
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name mirror.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name mirror.example.com;

    ssl_certificate /etc/letsencrypt/live/mirror.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mirror.example.com/privkey.pem;

    client_max_body_size 100m;
    large_client_header_buffers 8 64k;
    client_header_buffer_size 64k;

    location / {
        proxy_pass http://127.0.0.1:40002;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_buffering off;
        proxy_buffer_size 128k;
        proxy_buffers 8 128k;
        proxy_busy_buffers_size 256k;
    }
}

上传上限 100 MB 和 600 秒超时是本教程示例，可按需求调整；如果改了 PORT，同步修改 proxy_pass。

BASH · 加载反代配置
sudo nginx -t
sudo systemctl reload nginx
curl -I https://mirror.example.com/admin/

使用 Cloudflare 时，开启 WebSocket，源站安装有效证书，SSL/TLS 使用 Full (strict)。不要缓存登录、管理 API 或对话请求。

生产环境保持三个 Secure Cookie 选项为 true，并通过 HTTPS 登录。DJANGO_ALLOW_ALL_ORIGINS=disable 时启用明确的域名与 CSRF 白名单。

04

登录后台，开始第一次对话

访问 https://mirror.example.com/admin/，使用 .env 中设置的管理员账号登录，然后依次完成：

  1. 添加上游账号在「上游账号」录入你有授权的 Cookie 或 Refresh Token，检查状态，必要时刷新凭据。
  2. 组织账号池在「账号池」中添加可用账号，为镜像用户分配对应的访问范围。
  3. 配置用户权限在「用户」里创建用户，设置可用模型与使用限制。需要代理时，在「代理」中配置并测试连通性。

管理后台为 Vue 管理界面，不是 Django 原生 admin。管理员修改用户权限或密码可能导致该用户的活跃会话退出。

05

数据备份、镜像更新与恢复

下列示例在项目目录的 Bash 中运行。当前编排的数据分布在 data/、backend/db/ 和 backend/logs/；.env 中的加密密钥也要一起妥善保存。

备份、更新与恢复步骤 ＋

1. 先备份。短暂停机可避免拷贝正在写入的 SQLite 数据。备份包含凭据，存放在受控目录，不要提交到 Git 或公开网站。

BASH · 一致性备份
mkdir -p ../mirror-backups
chmod 700 ../mirror-backups
umask 077
docker compose stop
tar -czf "../mirror-backups/mirror-$(date +%Y%m%d-%H%M%S).tar.gz" \
  .env docker-compose.yml data backend/db backend/logs
docker compose start

2. 检查上游变更，再更新镜像。先记录当前镜像 ID / digest；查阅新版本配置差异，保留本地回环端口修改。下列命令仅更新容器镜像，不会同步 Git 配置文件。

BASH · 更新服务
docker compose images
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100
curl -fsS http://127.0.0.1:18000/0x/user/version-cfg

3. 恢复备份。遇到更新异常时，先停止服务，将备份解压到独立目录，再恢复数据库、原始加密密钥以及与备份匹配的镜像版本。不要覆盖正在运行的数据库。

不要随意更换 CREDENTIAL_ENCRYPTION_KEY；丢失原始密钥可能使已有加密凭据无法解密。

常见问题

这是 OpenAI 官方项目吗？可以商用吗？＋

这是 Jasa-Chi-Ray 本人维护的第三方项目，与 OpenAI 官方无隶属关系。只允许个人学习、研究和其他非商业用途；商业使用需要事先取得作者书面许可。部分组件并未开源，具体以仓库许可说明为准。

部署后就能免费使用所有模型吗？＋

不能。你仍需要有授权且有效的上游账号；模型、额度和功能由账号权限及上游服务决定。镜像站提供使用和管理入口，不会额外授予订阅或模型使用权。

登录失败、CSRF 报错或反复退出怎么办？＋

先检查浏览器使用的域名是否包含在 DJANGO_ALLOWED_HOSTS 中；DJANGO_CSRF_TRUSTED_ORIGINS 必须含正确协议，非默认端口也要填写。确认 NGINX 转发 Host 与 X-Forwarded-Proto。VPS 的 HTTPS 访问保持三个 Secure Cookie 选项为 true。修改 .env 后运行 docker compose up -d 重建服务。

出现 400、414 或 upstream sent too big header？＋

参照部署指南中的 NGINX 配置，增加 client_header_buffer_size、large_client_header_buffers 及代理响应头缓冲。先用 nginx -t 检查，再 reload。如果前方还有 CDN 或其他反代，也要查看它们的请求头与 URL 长度限制。

页面能打开，但消息中断或一直加载？＋

检查 NGINX 与 Cloudflare 的 WebSocket 支持、上游账号凭据和代理连通性，查看 chatgpt-mirror、django、cfbypass 三个服务的日志。浏览器网络面板中检查失败请求。

可以完全避免“降智”或保证账号隔离吗？＋

不能作此保证。项目持续改善相关体验，但仓库复测只是特定时间与环境的结果。curl-impersonate 等方案属于实验性能力。共享账号隔离仅覆盖镜像可控制的范围，不等同于独立上游账号之间的隔离。

可以一键部署自己的 ChatGPT 镜像站点吗？＋

填写 .env 中的密码、密钥与域名后，可以用 docker compose up -d 启动仓库中的三个服务。账号录入、DNS、证书和 NGINX 反代仍需配置，具体步骤见上方 VPS 部署教程。

自己部署 ChatGPT 镜像站是免费的吗？＋

项目允许按仓库许可用于个人学习、研究等非商业用途，但自建站点仍可能产生 VPS、域名和上游账号订阅费用。部署镜像站不会自动获得免费模型额度，可用模型和功能取决于上游账号。
